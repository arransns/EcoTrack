# Contributing to EcoTrack

Thank you for your interest in EcoTrack.

EcoTrack is primarily developed as an educational and research project.
Contributions, suggestions, and issue reports may be considered when they help
improve the quality, accessibility, performance, or reliability of the project.

---

## Before Contributing

Before proposing a change:

1. Review the existing project and documentation.
2. Make sure the proposed change is relevant to EcoTrack.
3. Avoid changing the core visual identity without a clear reason.
4. Preserve compatibility with the existing experience.
5. Do not introduce unnecessary dependencies.

---

## Development Principles

Changes should maintain the following EcoTrack principles:

- Clean and professional UI/UX
- Environmental technology identity
- Responsive design
- Good performance
- Accessibility
- Smooth and purposeful motion
- Clear user experience
- Maintainable code
- Minimal unnecessary complexity

---

## Reporting Bugs

When reporting a bug, provide:

- A clear description
- Steps to reproduce the problem
- Expected behavior
- Actual behavior
- Browser and device information
- Screenshots when relevant

---

## Feature Suggestions

Feature suggestions should explain:

- What problem the feature solves
- How it improves EcoTrack
- Who would benefit from it
- Any potential impact on usability or performance

---

## Pull Requests

Pull requests should:

- Focus on a specific improvement
- Avoid unrelated changes
- Preserve existing functionality
- Avoid unnecessary code duplication
- Remain responsive on desktop and mobile
- Avoid introducing console errors
- Be tested before submission

Large visual or architectural changes should be discussed before implementation.

---

## Code Style

Keep code:

- Readable
- Organized
- Consistent
- Clearly named
- Properly formatted
- Free from unnecessary dependencies

Comments should explain important or non-obvious behavior rather than describe
every line of code.
